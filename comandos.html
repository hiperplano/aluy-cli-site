reference

Every command, in one place.

Two surfaces, in the order you meet them. In your shell you call aluy with subcommands and flags. Once a session is open, slash commands are what you type inside it. This page is the complete list of both, grouped by what you are trying to do. If you are still learning what to reach for, start with the guide.

The command line Session commands
in your shell

The aluy command line

Open a session

— the default, with no subcommand.
aluy [goal] [flags…]

Opens the interactive session in the current directory. A quoted string is taken as the starting goal. The first run opens the setup assistant first.

$ aluy "add a health check endpoint to the API"
--continue

Resumes the last session of this directory.

--resume [<id>]

With no id, lists the saved sessions to pick from. With an id, resumes that one.

$ aluy --resume 3f9c1a2b
--new

Starts a fresh session, ignoring the saved ones.

--telegram

Opens the session with the Telegram bridge on, so the agent can reach you off the terminal.

Decide how much it may do

— the setting that matters most.
--plan

Read-only planning: the agent analyzes and proposes, and produces no effect. If you pass both, this one wins over --yolo.

--yolo

Auto-approves every effect, except the always-ask categories, which cannot be relaxed. Refuses to run as root. In a terminal it confirms once; in headless mode it enters directly.

Deprecated alias: --unsafe (still works, warns).

--no-subagents

Turns off parallel subagents. By default they run at depth 1 or less, inheriting the parent’s permissions and sharing one ceiling.

Run it without a session

— scripts, pipes and CI. All of these need -p.
-p
--print
--exec "<goal>"

Runs one goal, prints the result and exits. The goal can be inline or piped on stdin.

$ aluy -p "which files changed today?"
--output-format text|json|stream-json

How the result comes back: just the text, a single JSON object, or a live stream of events, one JSON object per line.

$ aluy -p "list the open TODOs" --output-format json

Default: text.

--quiet

Suppresses the progress ticks and the stderr noise, leaving only the result.

--cycles <N>
--cycle-for <dur>

Runs the goal autonomously in cycles — the headless form of /cycle. A ceiling is required: iterations with the first, wall-clock time with the second.

$ aluy -p "fix the failing tests" --cycles 5
    durations
  • 30m
  • 2h

Both are capped at a hard limit you cannot raise. --cycle is the bare form.

Choose the model

— which one answers, and how it is reached.
--tier <tier>

Picks the model tier for the session. Changeable at runtime with /model.

$ aluy --tier aluy-flux

Passing "custom" without --model is a usage error.

--model <slug> [--provider <name>]

Selects a curated model from the catalog and forces the custom tier. The two must be passed together.

$ aluy models # lists the slugs --model accepts

Both are data, never a credential — that is resolved locally.

--effort <value>

Reasoning-effort passthrough: any non-empty value up to 32 characters. No tier gate; your provider validates it.

$ aluy --effort high
    typical
  • low
  • medium
  • high
--backend local|broker

Local calls your provider directly with your own credential; nothing is routed through or counted by Aluy. Broker routes through a central backend, which is not available today.

$ aluy --backend local

Default: local.

--local-provider <name>

Which provider the local backend talks to.

$ aluy --backend local --local-provider anthropic
    values
  • anthropic
  • openrouter
  • openai
--local-model <slug>

The model slug, exactly as that provider names it.

$ aluy --local-provider openai --local-model gpt-4o
--local-auth apikey|oauth

A stored API key, or a subscription OAuth sign-in.

$ aluy --local-auth oauth
--local-base-url <url>

The endpoint to call, for an OpenAI-compatible provider or a local runtime. Aluy refuses addresses that would make it call back into your own private network.

$ aluy --local-base-url http://127.0.0.1:11434/v1

The four --local-* flags need --backend local, and fall back to ALUY_LOCAL_* or config.

Set the ceilings

— so a run cannot go all night on your budget.
--max-tokens <N>

The session token budget.

$ aluy --max-tokens 250000

Default: 1000000. Capped at a hard limit.

--max-iterations <N>

Caps the model → tool → observation loop.

$ aluy --max-iterations 40

Default: 300. Capped at a hard limit.

--max-output-tokens <N>

Caps the output of a single model call. On reaching any of these three ceilings, the run pauses and asks whether to continue or stop.

$ aluy --max-output-tokens 8000

Capped at a hard limit.

--budget
--no-budget

Toggles the session budget circuit-breaker.

Off by default on the local backend (your own key, unlimited by design); always on with the central backend.

--self-check
--no-self-check

Forces the self-check loop on or off: re-anchor the objective and verify before declaring the work done.

With no flag it is automatic — weaker tiers turn it on.

--autocompact-at <ratio|%|off>

How full the model’s window may get before Aluy compacts the conversation.

$ aluy --autocompact-at 90%
    accepts
  • 0.85
  • 85%
  • off

Default: 0.85. --no-autocompact equals --autocompact-at off.

Change how it looks

— all of these persist to config.
--lang pt-BR|en

Interface language. It does not translate the agent’s output. /lang toggles it at runtime.

$ aluy --lang en

Precedence: flag > config > locale auto-detect > pt-BR.

--split

Starts in Advanced View, with CHAT and LOG side by side. Ctrl+L toggles it.

--fullscreen

Starts in Cockpit mode, which takes over the whole terminal and restores what was there when you leave.

--dense

Compacts the interface — less padding, more content per screen.

--ascii

Switches to a safe symbol set, for fonts that show empty boxes instead of symbols.

Same as ALUY_SAFE_GLYPHS=1.

Set up the install

— subcommands: they do one job and exit.
aluy onboard

Guided setup: language, backend, provider, key, model, the MCP servers it offers, and the sidecar profile. Step 2 right after the install, and you can run it again to switch.

aluy bootstrap [--no-agent]

Installs the optional local programs — memory, context compression and local models — under your own user account. It offers each one and you choose. By default it installs them through its own agent; --no-agent takes the direct, deterministic path with no model involved.

$ aluy bootstrap --no-agent
    sidecars
  • mem0
  • headroom
  • ollama
aluy config

Prints what is actually in effect — profile, toggles, and where each setting came from.

aluy login

Authenticates. With a provider, it stores that provider’s API key in your vault; with OAuth, it signs you in with a subscription instead. With neither, it runs the device flow of the central backend.

$ aluy login --provider anthropic
    options
  • --provider <p>
  • --oauth
  • --token <token>
  • --org <id>
  • --device

Subscription OAuth in a non-official client is a grey area in the provider’s terms — it is your call. --token is for CI.

aluy logout
aluy whoami

The first revokes the session and erases the stored credential. The second shows user, org and scopes — never the secret.

Check and inspect

— read-only; no model call, exit 0.
aluy doctor [--deep|--test] [--json]

Validates the install: credential, provider reachability, MCP servers, agent profiles, config, version and memory.

$ aluy doctor --deep --json

--deep adds a live tier test, which costs one model call. --json prints a machine-readable array; exit code is non-zero if a check fails.

aluy agents

Read-only listings of what Aluy mapped: agent profiles, skills, workflow definitions, and the providers and models available to you.

    and also
  • skills
  • workflows
  • models
  • providers
-v
--version

Prints the version and exits before the interface mounts.

Format: aluy <cli> (@hiperplano/aluy-cli-core <core>).

-h
--help

Prints the full built-in help — every command and flag — and exits.

Leave work running

— scheduled tasks and services.
aluy cron <when> "<task>"

Schedules persistent headless tasks through the OS scheduler, with no daemon. Each run executes headlessly, through the permission gate.

$ aluy cron add "0 9 * * 1-5" "summarize the commits from yesterday"
    subcommands
  • add
  • list
  • edit
  • enable
  • disable
  • rm
  • run

Live on Linux (crontab); Windows and macOS to come. "add" takes a 5-field cron, such as "0 9 * * 1-5".

aluy service <name>

Agents with a routine. Starting one shows you the manifest and asks first; attaching puts you inside a running service to watch and steer it, and Ctrl+C detaches without stopping it.

$ aluy service start nightly-tests
    subcommands
  • list
  • status
  • create
  • install
  • uninstall
  • start
  • stop
  • logs
  • attach

start --group and stop --group operate a whole table of services at once.

Connect external tools

— the same engines as the in-session commands.
aluy mcp <name>

Manages MCP connectors from the shell. Adding one takes a name and the command that starts the server.

$ aluy mcp add local-db -- ./scripts/db-mcp.sh
    subcommands
  • search
  • add
  • list
  • remove

--project writes to the project .mcp.json instead of the global one.

aluy telegram <chat-id>

Connects the bot that reaches you off the terminal. Signing in stores the @BotFather token in your vault, and the allowlist starts closed.

$ aluy telegram allow 123456789
    subcommands
  • login
  • logout
  • allow
  • deny
  • status

"status" shows the token redacted, the allowlist and the bridge state.

Anti-runaway guards

— they stop a run that is busy but going nowhere. All are on by default.
variableflagwhat it does
ALUY_DEGENERATE_*
—

The repeated-output guard, which aborts a reply that keeps saying the same thing: how many identical lines in a row are allowed (default 25), how long a repeating cycle may run (default 2000 characters), and a switch to turn the guard off.

$ export ALUY_DEGENERATE_LINE_REPEATS=40
ALUY_STUCK_*
—

The stuck watchdog, which pauses and asks you for direction instead of spinning: the same tool called four times, the same error three times, three empty turns, six iterations without progress — and a switch to turn it off.

$ export ALUY_STUCK_SAME_TOOL=6
ALUY_CONT_*
—

What happens when the model says it will use a tool and then does not: how many times Aluy may nudge it to carry on (default 4), when the nudge gets firm, when to give up, and a switch to turn it off.

$ export ALUY_CONT_MAX=2
ALUY_MAESTRO_OFF
—

The kill switch for the supervisor — the layer that watches the run and, when the sidecars are up, uses them to steer it. It never touches the permission gate.

ALUY_MAESTRO
—

The same thing, turned off explicitly with 0 or false rather than by the kill switch.

ALUY_MAESTRO_MEM0
—

Whether that supervisor may use the memory sidecar.

ALUY_MAESTRO_OLLAMA
—

Whether it may use the local judge.

ALUY_CYCLE_JUDGE_OFF
—

Turns off the judge that decides when a /cycle has finished.

Work with more than one agent

— your fleet, and the rooms they talk in.
/subagent <profile>

Opens a focused 1:1 sub-session with one profile. Each subagent keeps its own context, so a long task does not crowd out yours.

$ /subagent reviewer
/back

Leaves the subagent focus and returns to the main session.

/rooms [new|list|read|watch]

Creates and follows rooms where several agents talk to each other about the same problem, live.

$ /rooms watch
/agents

Lists the mapped agent profiles, global and project, valid and rejected with the reason.
